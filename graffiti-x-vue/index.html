Graffiti for Vue 3

This library lets you add custom social components to any static website via an extension to the Vue.js Javascript framework that interfaces with the Graffiti server. Specifically, the library exposes three properties:

  • toggleLogIn: A function that let's you log in and out of the Graffiti server via email.
  • myID: A unique string associated with your Graffiti account.
  • useCollection: A Vue Composable that let's you retrieve and modify dynamic collections of social data from the Graffiti server — this is where the magic happens!

# Collections

Collections of social data in Graffiti are formed by arbitrary queries rather than the directories of a file structure or the tables of a SQL database. We can interface with these collections in Vue with the useCollection composable. The composable takes a MongoDB query as input and returns three properties:

  • objects: a reactive array of all the objects in the server that match the input query.
  • update: a function to add or replace an object matching the query to the server.
  • remove: a function to remove an object matching the query from the server

Other than a couple regulated fields that start with _ described in the next section, data you put into Graffiti is schemaless. # Context

Boundaries are critical to maintaining healthy social relationships, and so one of Graffiti's core features is a powerful system for creating hard and soft boundaries around certain pieces of content. Hard boundaries are like those in traditional access control; only individuals you specify can access a piece of content. Soft boundaries are for content that is public but only intended for a specific audience. Consider a physical analogy. Say you sing at a karaoke bar at the weekend. Your singing is public because anyone can walk into the bar and see you sing. Still, it's unlikely that your colleagues will encounter you singing unless they are also karaoke enthusiasts.

In Graffiti, hard boundaries are actually a special case of soft boundaries so we will start with soft. We consider a soft boundary to be something of the form "I don't want people to see this unless they are specifically looking for X". We take a person "specifically looking for X" to mean that their query would fail on an object that does not include X.

In the example below we are querying for boops that have the tag "demo". tags, like type and all other properties not beginning with _, is just an arbitrary property name. Then, we are using two special properties _inContextIf and _queryFailsWithout to make one of our buttons only boop for people specifically looking for objects with the tag "demo".

The array _inContextIf can include multiple conditions and an object will be "in context" if any one of the conditions holds. The array _queryFailsWithout can include multiple properties and an object will be in context if the query fails without any one of them. It can also include groups of properties and an object will be in context if removing all of the properties in the group simultaneously causes the query to fail. And finally, in addition to _queryFailsWithout you can also use it's negation, _queryPassesWithout.

# Identity

In our examples we've made queries for the _by property. This special property is automatically included in all objects and must be equal to _myID. Therefore, noone can forge this "signature" on your objects. So far, it's allowed us to filter for only object we have created but you might also use it to compile information about a user. For example as your interface is parsing a list of comments, it could look up each commenters name to display. However the context system in the previous section means that just because an object is _by you, doesn't mean it can be found by simply querying for {_by: _myID}.

There is one more special field that will allow us to create Hard boundaries: _to. If you include it in your object, _to must be an Array of user IDs. The catch is that people can only query for things _to their own user ID. On it's own this does not that does not make the object private, but we can combine it with context to make it so.
